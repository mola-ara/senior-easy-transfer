# 바다송금 v2.0 제품 기획서

## 1. 서비스 정의

바다송금 v2.0은 연령이나 장애 유형으로 사용자를 구분하지 않고, 개인이 선택한 안내 수준과 지원 기능을 조합해 모의 송금을 반복 연습하도록 돕는 서비스임. 쉬운 표현과 일반 금융 용어를 단계적으로 함께 제공해 일반 금융 화면에 적응하도록 지원하는 것이 목표임.

v1.0이 고령 사용자와 가족·도우미를 중심으로 큰 글씨·음성 안내를 제공했다면, v2.0은 모바일 금융 경험과 필요한 지원 방식이 서로 다른 모든 사용자가 자신의 안내 방법을 직접 선택하도록 확장함. 기존 송금 도메인과 안전 확인 흐름은 그대로 공유함.

## 2. 핵심 사용자와 교차 특성

- 모바일 금융 경험이 부족한 사용자
- 금융 용어 또는 국내 송금 절차가 익숙하지 않은 사용자
- 큰 글씨, 음성, 높은 대비 또는 움직임 감소가 필요한 사용자
- 여러 지원 기능이 동시에 필요한 사용자

한 사람에게 연령, 시력, 언어 경험과 디지털 숙련도 등이 중첩될 수 있음. `고령자`, `장애인`, `외국인` 같은 단일 분류는 실제 필요한 UI 지원을 정확히 나타내지 못하고 불필요한 민감정보 수집으로 이어질 수 있으므로 사용자를 직접 분류하지 않음. 화면에 필요한 기능만 선택·저장함.

## 3. 핵심 가설과 측정 계획

### 가설 1. 직접 선택 가능한 안내 수준이 진입 부담을 줄일 수 있음

- 관찰할 행동: 안내 수준 선택·변경·자세한 안내 복귀, 첫 송금 시작과 완료
- 성공 판단 기준: 참여자가 원하는 설정을 도움 없이 선택하고 송금 연습을 시작할 수 있음. 목표 비율은 사전 표본 수 확정 후 설정 필요 `[확인 필요]`
- 필요한 이벤트: 안내 설정 화면 진입, 안내 수준 변경·복귀, 송금 단계 시작·완료
- 현재 측정 범위: 브라우저 내 프로필 저장과 E2E 동작 확인 가능
- 실제 사용자 테스트 필요: 진입 부담, 선택 문구 이해도와 도움 요청 여부 확인 필요

### 가설 2. 쉬운 표현과 금융 용어 병기가 용어 학습을 지원할 수 있음

- 관찰할 행동: 금융 용어 도움말 열기, 용어 확인 문항 결과, 이후 표준 표현 과업 완료
- 성공 판단 기준: 반복 과업 뒤 주요 용어의 의미를 설명하거나 올바른 화면 요소를 선택함. 대상 용어와 통과 기준은 사용자 테스트 설계 시 확정 필요 `[확인 필요]`
- 필요한 이벤트: 도움말 열기, 금융 용어 확인 결과, 단계 완료, 이전 단계 이동
- 현재 측정 범위: 안내 수준 선택과 화면별 문구 정책 구현 가능. 학습 효과 측정은 미구현
- 실제 사용자 테스트 필요: 용어 이해도 전후 비교와 표현별 오해 여부 확인 필요

### 가설 3. 결과에 근거한 안내 축소 제안이 점진적 전환을 지원할 수 있음

- 관찰할 행동: 연속 과업 완료, 수정·도움말·이전 이동, 축소 제안 수락·거절·복귀
- 성공 판단 기준: 사용자가 제안을 이해하고 직접 선택하며, 축소 뒤에도 송금 과업과 안전 확인을 완료함. 제안 조건과 성공 횟수는 검증 후 확정 필요 `[확인 필요]`
- 필요한 이벤트: 단계 시작·완료, 수취인 재선택, 금액 수정, 도움말 열기, 이전 이동, 안내 수준 변경·복귀
- 현재 측정 범위: 프로필의 수동 변경만 가능. 자동 제안과 학습 이벤트 저장은 제외
- 실제 사용자 테스트 필요: 제안 시점, 거절 부담, 표준 화면 전환 후 이해도 확인 필요

응답시간은 네트워크 대기, 음성 재생, 백그라운드 체류를 제외한 유효 상호작용 시간으로 분리해야 함. 느린 응답만으로 숙련도를 판단하지 않고 완료 여부, 수정 횟수, 도움말 사용, 이전 이동, 용어 확인 결과와 함께 보조 신호로만 사용함.

## 4. 이번 구현 범위

- `AssistanceProfile` 타입, 안전한 기본값, localStorage 저장·복원 구현함
- 기존 `bada-accessibility`의 큰 글씨·음성 설정 마이그레이션 구현함
- 세 안내 수준과 큰 글씨·음성·높은 대비·움직임 감소 선택 화면 구현함
- 설정 실패가 송금 흐름을 중단하지 않는 처리 구현함
- 기존 Playwright Core 기반 v1.0 핵심 흐름 E2E 기준선 추가함
- 49만 9천 원과 50만 원 경계는 단위 테스트와 E2E로 확인함

안내 수준별 전체 송금 문구 전환, 영어 문구, 학습 이벤트 수집, 반복 결과 기반 축소 제안은 후속 구현 예정임. E2E는 설치된 Chrome 실행 파일을 사용하는 현재 개발 환경 기준이며 CI 브라우저 설치 방식은 `[확인 필요]`임.

## 5. 제외 범위

- 실제 계좌·금융기관 API, 실자금 거래, 인증·인가 제외
- AI 또는 응답시간 기반 숙련도 자동 판정 제외
- 사용자 동의 없는 안내 수준 변경 제외
- 장애, 연령, 국적, 실제 계좌번호, 실명, 전체 키 입력값과 음성 내용 수집 제외
- 자동 번역 API와 영어 금융 확인 문구 제외
- 서버·데이터베이스 기반 프로필 및 학습 이벤트 동기화 제외

## 6. 개인정보 최소 수집 원칙

지원 기능의 동작에 필요한 안내 수준, 언어, 글자 크기, 음성, 대비, 움직임 설정만 현재 브라우저에 저장함. 장애 여부, 연령, 국적을 추론하거나 저장하지 않음. 학습 이벤트를 후속 도입할 때에도 실제 계좌번호, 수취인 실명, 전체 입력값과 음성 내용을 제외하고 목적·보유 기간·동의 방식을 먼저 확정할 필요 있음 `[확인 필요]`.

## 7. 항상 유지할 금융 안전장치

안내 수준과 관계없이 최종 수취인, 최종 금액, 위험 상황, 거래 실행 동의를 확인함. 오류와 미확정 거래 안내도 축소하지 않음. 안내 수준은 설명 문장, 금융 용어 노출 정도, 도움말과 한 화면의 정보량에만 영향을 줌.

## 8. 사용자 검증 계획

금융 경험과 필요한 지원 방식이 다른 참여자를 모집해 설정 선택, 수취인 선택, 금액 입력, 위험 확인, 최종 확인과 완료 과업을 관찰할 예정임. 도움 요청, 수정, 이전 이동, 용어 이해와 완료 여부를 함께 기록하고 응답시간은 보조 지표로만 사용함. 표본 구성, 인원, 사례비, 개인정보 동의서와 접근성별 보조기술 환경은 `[확인 필요]`임.
